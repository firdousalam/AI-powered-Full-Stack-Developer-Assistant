# 📖 What is MCP?

**Model Context Protocol (MCP)** is an open standard that enables Large Language Models (LLMs) to communicate with external tools, applications, and data sources using a common protocol.

Think of MCP as:

> **"USB-C for AI Applications"**

Just as USB-C provides a universal interface for connecting devices, MCP provides a universal interface for connecting AI models with developer tools such as GitHub, Docker, Kubernetes, databases, and local files.

Instead of building custom integrations for every tool, developers implement MCP once and gain access to any compatible MCP server.

---

# ❓ Why Do LLMs Need External Tools?

Large Language Models are excellent at generating text and reasoning over information, but they **cannot directly**:

* Read local project files
* Execute Git commands
* Build Docker images
* Deploy Kubernetes resources
* Query databases
* Access internal company APIs
* Execute shell commands

Without external tools, an LLM can only **suggest** commands.

### Example (Without MCP)

**User**

```text
Build my Docker image
```

**LLM**

```bash
docker build -t my-app .
```

The model only generates the command.

---

### Example (With MCP)

**User**

```text
Build my Docker image
```

Flow:

```text
User
   │
   ▼
LLM
   │
   ▼
MCP Client
   │
   ▼
Docker MCP Server
   │
   ▼
Docker Engine
   │
   ▼
Build Output
   │
   ▼
LLM explains the result
```

The AI can actually execute the task and return real results.

# 🏗 MCP Components

MCP consists of several building blocks.

## 1. MCP Client

The MCP Client connects the AI application to one or more MCP Servers.

Responsibilities:

* Discover available tools
* Execute tool calls
* Receive tool responses
* Pass results back to the AI model

In our project, the **Node.js Backend** will act as the MCP Client.

---

## 2. MCP Server

The MCP Server exposes tools and resources that AI models can use.

Examples:

* Filesystem
* GitHub
* Docker
* Kubernetes
* PostgreSQL
* MongoDB
* Redis
* AWS

Each server specializes in a specific domain.

---

## 3. Tools

Tools are executable functions exposed by the MCP Server.

Examples:

```text
read_file()

write_file()

docker_build()

git_commit()

kubectl_apply()
```

---

## 4. Resources

Resources are pieces of information the model can read.

Examples:

```text
README.md

package.json

Dockerfile

deployment.yaml

Source Code
```

---

## 5. Prompts

Prompt templates that can be reused by AI applications.

Examples:

```text
Explain this project

Generate unit tests

Review this code

Fix this bug
```

---

# 🔄 MCP Client vs MCP Server

| MCP Client                 | MCP Server                 |
| -------------------------- | -------------------------- |
| Runs inside AI application | Runs as a separate service |
| Discovers tools            | Provides tools             |
| Executes requests          | Performs operations        |
| Receives responses         | Returns results            |
| Talks to the AI model      | Talks to external systems  |

# 🌐 Transport Layer

MCP supports multiple communication methods.

## Standard Input / Output (stdio)

Best for local tools.

```text
Node Backend
      │
stdin/stdout
      │
Filesystem MCP Server
```

Advantages:

* Fast
* Local
* Secure
* Easy to configure

---

## HTTP / Server-Sent Events (SSE)

Suitable for remote MCP servers.

```text
Node Backend
      │
HTTP
      │
Remote MCP Server
```

Advantages:

* Network accessible
* Cloud ready
* Scalable

---

## WebSocket

Useful for real-time communication and long-running operations.

---

# 📦 JSON-RPC Communication

MCP uses **JSON-RPC 2.0** for communication.

## Request

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "read_file",
    "arguments": {
      "path": "README.md"
    }
  }
}
```

---

## Response

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": "Project Documentation..."
  }
}
```

JSON-RPC provides a standardized way for AI applications and MCP servers to communicate regardless of programming language.

# 🔒 Security Model

MCP is designed with security in mind.

Recommended practices include:

* User approval before sensitive operations
* Read-only vs Read/Write permissions
* Tool allow-listing
* Input validation
* Least-privilege credentials
* Audit logging

### Example

```text
AI wants to delete a file
          │
          ▼
Show confirmation dialog
          │
          ▼
User approves
          │
          ▼
Execute MCP Tool
```

This ensures users remain in control of potentially destructive actions.

# 📚 Key Takeaways

* MCP standardizes communication between AI applications and external tools.
* The Node.js Backend acts as the MCP Client.
* MCP Servers expose tools and resources.
* JSON-RPC provides standardized communication.
* Multiple transport layers are supported.
* Security is built around explicit tool execution and user control.
* MCP enables AI assistants to perform real-world operations instead of only generating suggestions.
